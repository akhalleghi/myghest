# بازبینی درخواست فروش چکی

مبنای طراحی، پاسخ تکمیلی مدیر سامانه است: **مشتریان چکی حتی در اطلاعات هویتی مستقل هستند** و هر پرونده می‌تواند چند چک داشته باشد. بنابراین ثبت مشتری و مدیریت پرونده در منوی جدید انجام می‌شود؛ شناسه‌های مشتری اقساطی به این بخش منتقل نمی‌شوند و پنل کاربر و پنجره وام اقساطی به پرونده چکی متصل نشده‌اند.

| درخواست | محل و رفتار نهایی |
| --- | --- |
| منوی جدا | مدیریت مشتریان چکی؛ جداول، دسترسی‌ها و مسیرهای مستقل |
| مشخصات و احراز مشتری | فرم ثبت/ویرایش مستقل، احراز اختیاری شماره و ابطال تأیید با تغییر شماره |
| تصاویر و مدارک | همان فرم انتخاب فایل، دوربین و فیلم بخش اقساط؛ ویرایش بعدی و تب نمایش مدارک؛ جدول و فایل‌های خصوصی مستقل |
| جدول مشتریان چکی | تعداد چک، جمع مبلغ اسمی با کارمزد، مانده روز، نزدیک‌ترین سررسید باز، کیف پول مستقل، وضعیت و دکمه پیامک، یادداشت و عملیات |
| افزودن پرونده | تاریخ خرید، سررسید واریز به مشتری، مبلغ خرید، تعداد ماه، نرخ و روش کارمزد، پیش‌پرداخت، تخفیف، ضرایب ثابت مخصوص همان قرارداد |
| یک یا چند چک | شماره صیاد یکتا، شماره چک، بانک، شعبه، مبلغ با کارمزد، سررسید، یادداشت؛ جمع چک‌ها دقیقاً برابر تعهد قرارداد |
| خریدار و دارنده متفاوت | مشخصات دارنده مستقل؛ نام پدر/کد ملی/آدرس اختیاری؛ تأیید پیامکی دارنده متفاوت الزامی و متصل به کل شرایط فرم |
| ضمانت توسط خود خریدار | تیک تعلق چک به خریدار؛ استفاده از مشخصات همان مشتری و احراز اختیاری |
| انتقال به بانک | نام بانک، شعبه، حساب، شبا و توضیح؛ مشخصات اضافی اختیاری و دارای کنترل قالب |
| انتقال به شخص | نام شخص، موبایل، کد ملی، آدرس و توضیح؛ مشخصات اضافی اختیاری |
| وصول و تشکر | ثبت دریافت جزئی/کامل، تفکیک اصل/دیرکرد/زودکرد و پیش‌نمایش قابل ویرایش پیام تشکر پس از تسویه |
| برگشت و اخطار | ثبت برگشت و پیش‌نمایش قابل ویرایش؛ الگوی دائمی در مدیریت پیامک |
| ارائه مجدد و برگشت دوباره | سابقه جدید مستقل؛ تاریخ اولیه و مبنای جریمه بازنویسی یا دو بار محاسبه نمی‌شود |
| عودت به دارنده یا خریدار | تأیید پیامکی موبایل همان گیرنده؛ مقصد و سابقه مشخص؛ عودت دوباره پیش از دریافت مجدد اصل چک مسدود |
| بایگانی‌ها | پوشه جاری، بانک، انتقالی، برگشتی، عودتی، بایگانی وصول؛ حذف فیزیکی رکورد انجام نمی‌شود |
| جزئیات | مشخصات کامل، خریدار، دارنده، شرایط قرارداد، مقصد فعلی، سایر چک‌های پرونده، دریافت‌ها و تاریخچه با نویسنده و زمان |
| یادداشت | فقط داخل پنجره و تب یادداشت؛ جمع یادداشت‌های مشتری/پرونده/چک در ردیف مشتری؛ متن بدون اجرای HTML نمایش داده می‌شود |
| پیامک | الگوهای قابل ویرایش، پیش‌نمایش و تأیید ارسال؛ یادآوری تجمیعی خودکار اختیاری و پیش‌فرض غیرفعال |
| گزارش/اکسل | نام کامل، موبایل، صیاد، شماره چک، بانک، پوشه، مبلغ، بازه خرید و سررسید؛ فیلتر یکسان و خروجی تمام صفحات |
| آمار سیستم | بخش مجزا برای ماه جاری، وصول، تسویه‌نشده، برگشتی، تعیین تکلیف اداری و سال قبل/جاری/آینده |
| نمودارها | ۱۲ ماه قبل، ماه جاری و ۱۲ ماه آینده، ۹ سال قبل تا سال آینده؛ بر اساس سررسید شمسی و جدا از وام |
| محافظت مالی | قفل تراکنش، نسخه چک، شناسه دریافت یکتا، کنترل سقف پرداخت در همان تاریخ و رد نتیجه دیررس فرم دیگر |
| سازگاری استقرار | جدول‌های افزایشی، عدم بازنویسی قالب‌های قدیمی، عدم تغییر مشتریان و محاسبات اقساطی، توقف rollback در صورت وجود داده چکی |

**تفکیک ضروری آمار:** بنا بر انتخاب «بهترین حالت»، وصول پول و تعیین تکلیف اداری یکسان محسوب نمی‌شوند. چک برگشتیِ انتقال‌یافته یا عودتی از پوشه برگشتی خارج و در آمار تعیین تکلیف قرار می‌گیرد، اما تا دریافت وجه بدهی آن باقی است. این موارد به‌عنوان «وصول واقعی» گزارش نمی‌شوند.

**بازه گزارش:** بازه خرید و سررسید، پرونده‌ها و چک‌ها را فیلتر می‌کند؛ مانده‌ها وضعیت امروز هستند. بازسازی مانده حساب در تاریخ گذشته، موضوع جداگانه‌ای است و با این فیلتر ادعا نمی‌شود.
